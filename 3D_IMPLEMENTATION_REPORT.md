## Architecture actually implemented
- `GiftStage.tsx`: shared lazy/Suspense wrapper and error boundary. `NativeGiftCanvas.tsx`: shared React Three Fiber Canvas, on-demand/reduced-motion rendering, selected-scene lifecycle, quality selection, DPR caps and sustained-slow-frame downgrade, pointer ray picking with keyboard-equivalent HTML controls.
- `giftFactory.ts`: maps each real gift to its actual native factory. `giftWorlds.ts`: thirteen distinct factories (including distinct cassette and vinyl branches in one audio mechanism builder). Existing native letter, flower, crown and portal factories reused/improved.
- Non-gift chapters keep their working direct Three.js renderer. `scenePrimitives.ts` breaks the former runtime/helper import cycle. No whole-app framework migration.
- One focused WebGL Canvas, not seventeen live gallery canvases. Gallery uses **offline renders of the actual native objects**, encoded as lazy WebP images (17 total 107,438 bytes after final refresh), keeping labels/states/progress as HTML. These previews are static, not falsely advertised as live orbitable mini-canvases.
- `previewGiftModels.ts` and `scripts/render-gift-previews.mjs`: sequential preview authoring, one renderer reused then disposed. No generated AI photographs/assets, no downloaded proprietary models.
- Environments and materials: studio key/fill/hemi, warm/cool contrast, physical materials. Medium/high tiers use reduced-resolution PMREM room reflections; low skips this expensive room-render startup path and uses a tiny generated studio reflection approximation instead. Glass high tier uses transmission, lower tiers use an explicitly optimized transparent approximation. No costly DOF/physics forced on mobile.
- Explicit geometry/material/texture/instancing/shadow cleanup in `disposeTree.ts`; timeline cleanup and stale async image request disposal. R3F owns renderer cleanup. No heap/GPU leak certification claimed.
- Desktop gift experience shell redesigned into a large native stage beside an HTML instrument/copy console; stacked on smaller displays. Native dialog semantics/Escape/focus preserved.

## Honest limitations
- Procedural objects are stylized, not photoreal scanned models. Some scenes still have simple shapes, simplified fabric and no physically traced caustics/optics. This is not a claim of film-quality photorealism.
- Glass/reflection quality intentionally differs by tier. Medium/high shadow/reflection behavior still needs real-device validation.
- Handwriting uses original text texture/HTML and short masks, not custom stroke-traced glyphs. Coupon turning leaf is bent but not a full multi-sheet cloth simulation. Open-when cabinet has hinged flaps, not four complete gift01 extraction rigs.
- No supplied real audio/photos means real playback, voice fidelity, music-reactive response and photo framing are not yet end-to-end certified. WebAudio analyser implementation alone is not a tested supplied-audio experience.
- Native gift models are procedural runtime code; existing GLB files are historical static snapshots unless explicitly refreshed. No Draco/KTX compression claim. Static WebP gallery textures are compressed.
- No measured hardware 60 FPS, real mobile Safari/Firefox coverage, Lighthouse budget or complete screen-reader/contrast audit. Browser tests use software Chromium and are not hardware performance measurements.
- Main botanical chapter retains its earlier native multi-flower garden. This pass prioritizes the requested seed/soil transformation in gift03 and the Future Garden gift15; it does not claim every outdoor chapter/environment was completely rebuilt.
- All 17 have native objects, but the full creative standard still requires further art direction, device QA and owner assets. Do not call the entire master brief finished solely because all scenes render.
